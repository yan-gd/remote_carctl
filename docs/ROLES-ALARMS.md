# 四角色权限与导航告警

对应《顺利上岸队 v3.0》中的用户角色、报警确认、日志查询要求，以及本轮「删除巡检卡片、导航障碍进入告警」的补充需求。实现位于前端、后端及小车桥接三部分，不能只更新网页。

## 登录后的权限

| 角色 | 页面操作 | 日志范围 |
| --- | --- | --- |
| OPERATOR · 远程巡检操作员 | 遥控、建图、定位、选点导航、停止；告警只读 | 本人 |
| MONITOR · 安全监控值班员 | 默认进入告警；确认告警、紧急停止、取消导航；地图只读，不能启动运动 | 本人 |
| MAINTAINER · 现场设备运维员 | 查看设备、地图、视频、告警；不能驾驶或确认告警 | 全部 |
| VIEWER · 业务查看人员 | 查看设备、地图、视频、告警；不能驾驶或确认告警 | 全部 |

角色来自服务端用户记录，不在浏览器中选择或自行提权。后端继续校验权限，隐藏按钮不能代替接口鉴权。公开注册仍固定 VIEWER。若部署已开启演示数据，既有账号为 `demo_operator`、`demo_monitor`、`demo_maintainer`、`demo_viewer`；使用部署时设置的密码。初始化不会覆盖已有账号密码，本次也不重置账号。

「巡检」导航入口及页面挂载已删除，原有路线/任务数据库记录与后端接口保留。导航页的真实地图导航和多点巡逻仍保留。

## 告警处理

- 告警列表每 3 秒更新，支持级别、状态、起止时间和分页。其他页面显示待确认总数及告警入口。
- 仅 MONITOR 显示「确认告警」。确认后持久化 `ACKNOWLEDGED`、确认人 ID、确认时间，并写入操作日志；历史记录不会被删除。
- 重复点击在前端拦截；其他值班员已经确认的 409 冲突会提示并重新同步。
- 按文档，确认表示值班员已知悉。没有新增“已解决”状态，也不会因为确认告警而恢复导航或解除停止保护。
- `DEMO_FIXTURE` 明确标为演示记录；实际设备告警展示来源、原因和处理建议。

## 导航障碍告警

小车使用现有 `/patrol/map_scan`（真实激光经 TF 投影）与同坐标系位姿，将点变换到车体方向。ACTIVE 导航期间，车体 `base_link` 原点前方 `0 < x <= 0.8m`、左右各 `0.35m` 区域内至少两个有效回波，作为近距离障碍证据。距离是前向距离，不是保险杠净距离，也不是目标路径全程碰撞预测。

- 云和位姿接收时间最多相差当前 0.75 秒；激光 ROS 时间最多偏离当前 1 秒，云与位姿时间戳差最多 0.3 秒。坐标系不一致、缺失、过期、空点云或无有限坐标均报告未知。
- 后端在在线心跳有效、同一任务中收到持续至少 0.5 秒的障碍报告后，写入一条 WARNING，来源 `SCOUT-001:NAV_OBSTACLE`。连续至少 2 秒明确无近距离障碍才允许下一次障碍产生新告警；未知数据不算清除。去重状态保存在内存，服务重启后会重新评估。
- 任务 ABORTED/REJECTED 或停滞、过度旋转、定位/健康丢失、超时等异常取消，另记 `SCOUT-001:NAVIGATION` 告警。规划失败不被冒充为检测到障碍，人工取消不生成异常停止告警。
- 原有运动仲裁、局部规划避障和停车保护保持生效。此功能只上报告警，不发布速度、不自动重启任务。纯里程计 `--direct` 模式没有障碍感知，不生成障碍检测报告。
- 这是近距离激光告警，不包含视觉物体类别识别。阈值需结合实车几何、激光外参与现场环境验收，不能替代规划器和现场急停。

## 更新与验收

1. 先停车并退出旧小车启动进程，再更新到同一版本。
2. 服务器按既有部署方式重新构建 Maven 后端并重启 `remote-carctl`；重新构建、发布前端 `dist`。无需修改数据库结构、账号、密钥或 MQTT ACL，复用已有导航状态话题。
3. 小车更新整个 `robot-bridge`，包含新增 `scout_obstacles.py`，在原仓库执行 `bash robot-bridge/start-scout.sh --web-map`。部署细节参见 [Web 建图说明](WEB-MAPPING.md)。无需新增 Python 依赖。
4. 分别登录四种角色，核对控制入口、地图操作、停止、告警确认及日志范围。用 MONITOR 确认一条告警，再刷新或重新登录，应看到相同的确认人和时间。
5. 现场按原导航验收流程验证近距离障碍上报、持续障碍不刷屏、移除后重新出现产生新告警、未知数据不当作清除。不要仅为生成告警而关闭避障或停车保护。

本地测试与浏览器夹具验证不等于实车验收；目前未远程部署，也未验证现场激光触发效果。
