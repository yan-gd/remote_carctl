# remote_carctl 接口测试报告

本报告由 `tests/api/render_report.py` 根据真实 pytest 结果生成，数字没有手填。本分支只有测试和报告，不含快照修复。用例表和时延来自对修复构建的复跑；初次在 main 上发现缺陷的记录单独保留。

## 1. 项目概述

remote_carctl（仓库内亦称 exp3）是松灵 SCOUT MINI 的远程控制与巡检管理平台，前后端分离，小车侧经 MQTT 接入。

| 部分 | 技术 | 职责 |
| --- | --- | --- |
| `backend/` | Java 17、Spring Boot 2.7.2、Spring Security、JWT HS256、MyBatis、SQLite、Eclipse Paho | 认证与权限、路线/任务/告警/日志、机器人控制、导航租约、摄像头转发、Web 建图命令邮箱 |
| `frontend/` | React 19、TypeScript、Vite 7 | 浏览器控制台。WHEP 地址由前端发给同源 nginx，不在本次后端进程内 |
| `robot-bridge/` | Python、paho-mqtt、可选 ROS1/ROS2 | 把 `robot/{id}/control` 转成速度指令，上报心跳、状态和回执。`--ros sim` 可在无硬件时替身底盘 |
| `server/media/mediamtx.yml` | MediaMTX | RTSPS 收流和本机 WHEP。需要证书、发布密码和 nginx 鉴权，本次未启动 |

业务代码扫描范围是 `org.example.patrol`。`exp2-adapter` 里的 `/helloworld`、`/customer` 示例控制器没有注册到运行中的服务。

统一响应为 `{"code","message","data"}`。成功码是 `SUCCESS`。参数错误返回真实的 4xx/5xx，而不是 HTTP 200。除注册和登录外，HTTP API 使用 `Authorization: Bearer <JWT>`。摄像头和建图的设备入口使用请求头 `X-Device-Key`。

## 4. 测试策略

- 不修改业务代码。服务以 `java -jar` 启动，测试只通过 HTTP 和 MQTT 访问。
- 正常用例覆盖登录、四种业务角色、管理员、路线任务闭环、告警确认、机器人在线控制和建图/摄像头/导航的成功路径。
- 边界用例覆盖用户名和密码格式、未知 JSON 字段、分页上下限、yaw 与相对距离、非法命令、超大 JPEG、栅格尺寸。
- 权限用例覆盖未登录、错误密码、过期 JWT、停用账号、角色不允许的写操作、设备密钥、管理员保护。
- 异常用例覆盖不存在的资源、重复确认、引用约束、MQTT 关闭、机器人离线、摄像头未配置。
- 小车和 ROS 用两种替身：Paho 直接发协议，以及仓库自带的 `SimAdapter`。断言只接受代码里写明的状态码和 `code`。
- Postman 集合在 `tests/api/postman/remote_carctl.postman_collection.json`，便于手工导入。自动化结果以 pytest 为准，本次没有另跑 Newman。

## 7. 缺陷

复跑没有失败用例。下面是初次在 main 上记录到的缺陷；修复提交在 PR #2，不在本分支。

快照接口当时声明 `produces = image/jpeg`。未配置摄像头时控制器抛出 `CAMERA_DISABLED`，异常处理却要写 JSON。`Accept: image/jpeg` 写不回 JSON，变成空的 HTTP 500。`Accept: application/json` 在进入方法前协商失败，通用处理写成 HTTP 500 / `INTERNAL_ERROR`。成功取帧在 `Accept: */*` 下仍返回 JPEG。

### 初次运行缺陷 1：OFF-10 未配置摄像头密钥且 Accept 为 JPEG 时，快照应返回 503 JSON

- 严重程度：中。成功取帧不受影响，失败响应被写成 500。
- 接口：`GET /api/v1/camera/snapshot`
- 当时期望：HTTP 503 / CAMERA_DISABLED
- 当时实际：HTTP 500 / 无 JSON 业务码 
- 响应片段：<binary 0 bytes b''>

### 初次运行缺陷 2：OFF-13 快照接口在 Accept 为 JSON 时应返回 406

- 严重程度：中。成功取帧不受影响，失败响应被写成 500。
- 接口：`GET /api/v1/camera/snapshot`
- 当时期望：HTTP 406 / 无独立业务码
- 当时实际：HTTP 500 / INTERNAL_ERROR 服务器内部错误
- 响应片段：{"code":"INTERNAL_ERROR","message":"服务器内部错误","data":null}

复跑把 OFF-13 的期望改成 HTTP 503 / `CAMERA_DISABLED`，并改用 PR #2 的 JAR。OFF-10 与 OFF-13 的复跑结果见第 5 节。

## 8. 风险与改进建议

- WHEP、RTSPS 和真实 ROS/CAN 没有在这台机器上运行。仿真桥不验证避障、定位和编码器延迟，不能代替实车验收。
- 摄像头用例使用 4 字节最小 JPEG，只验证帧边界和鉴权，不验证解码画质。观看上限用例会占用最多 8 个服务端阻塞线程数秒。
- 导航障碍告警依赖心跳在线和连续两次障碍报告的时间差，现场激光阈值仍需实车确认。
- 建议把 `backend/docs/API.md` 更新到与 OpenAPI 一致，并把 `tests/api/run.sh` 放进持续集成。CI 只需 JDK、Python 和 Mosquitto，不需要小车。
- 设备密钥、演示密码和 JWT 测试密钥只用于本套件的临时库。部署时必须更换，并且不要把 `PATROL_ADMIN_PASSWORD` 留在环境文件里。
- 未知路径在未登录时返回 401 而不是 404，这与 `anyRequest().authenticated()` 一致。调用方不能靠 401/404 判断路径是否存在。
